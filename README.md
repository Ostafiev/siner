# SINNERGEMS

Вёрстка сайта по макету из Figma «Siner for AI». Next.js 15 (App Router) + TypeScript + CSS Modules. Внешних зависимостей у рантайма нет — шрифты и картинки лежат внутри проекта.

## Запуск

```bash
npm install
npm run dev        # http://localhost:3000
```

Прод-сборка:

```bash
npm run build && npm start
```

Статическая сборка (если хостинг без Node — обычный nginx, Vercel static, любой S3):

```bash
STATIC_EXPORT=1 npm run build   # результат в /out
```

## Шрифты

| В макете | Сейчас в проекте |
|---|---|
| Forum | Forum, self-hosted через `@fontsource/forum` — совпадает |
| TT Firs Neue | **Manrope** как временная замена |

TT Firs Neue — коммерческий шрифт студии TypeType, скачать его нельзя. Когда будут файлы лицензии, положите их в `public/fonts/` ровно с такими именами:

```
public/fonts/TTFirsNeue-Regular.woff2
public/fonts/TTFirsNeue-Medium.woff2
public/fonts/TTFirsNeue-Bold.woff2
```

`@font-face` для них уже описан в `app/globals.css` и стоит первым в стеке — шрифт подхватится сам, править код не нужно. Если у вас `.otf`/`.ttf` — сконвертируйте в `.woff2` (например, через `fonttools`), так страница грузится заметно быстрее.

## Картинки — временные

Все изображения в `public/img/` вырезаны из присланных PNG-макетов и увеличены. Для проверки вёрстки годятся, для боевого сайта — нет: макет был в 1x, детали мылят.

Что нужно выгрузить из Figma и заменить:

| Файл | Что это | Как выгружать |
|---|---|---|
| `hero-desktop.jpg`, `hero-mobile.jpg` | первый экран | JPG 2x. В макете это похоже на кадр из видео — если планируется видео, скажите, поменяю `<picture>` на `<video>` |
| `ornament.png` | розетка на карточках | PNG с прозрачным фоном, 2x. Сейчас вырезана из макета по яркости |
| `logo-mark.png` | знак в мобильной шапке | лучше SVG |
| `bead-1…4.png` | бусины в карусели | PNG с прозрачным фоном, 2x |
| `news-1…5.jpg` | фото новостей | JPG 2x |

Логотип «SINNERGEMS» в шапке сейчас набран шрифтом Forum с золотым градиентом. Если есть оригинальный SVG — пришлите, поставлю его.

## Что отличается от макета (осознанно)

- **Шапка липкая.** При скролле остаётся сверху и слегка затемняется. В макете статичная — если не нужно, уберите `position: sticky` в `Header.module.css`.
- **Мобильное меню** нарисовано мной: в макете есть только иконка бургера, самого меню нет. Пункты берутся из `nav` в `lib/data.ts`.
- **Кружок «о нас»** показан только на мобильной версии — так в макете. Если нужен и на десктопе, скажите.
- **Пустые состояния корзины и избранного** придуманы с нуля — в макете их нет.
- **Кнопка в корзине — «Отправить заявку»**, а не «Перейти к оплате»: оплаты на
  сайте нет, менеджер связывается сам. Согласовано с заказчиком.
- **Новости, статья и текстовые страницы** нарисованы мной — макетов на них не
  было. Лента говорит на языке блока новостей с главной. Тексты черновые:
  статьи в `lib/news.ts`, страницы в `lib/pages.ts`.
- **Правовые страницы** — только структура разделов с видимым предупреждением.
  Юридический текст должен подготовить юрист магазина.
- **Десктопная раскладка конструктора временная** — холст слева, меню справа.
  Ждём десктопный макет.

## Анимации

- блоки появляются снизу при попадании во вьюпорт (`lib/useReveal.ts`);
- карусель: точки, свайп пальцем и мышью, стрелки на клавиатуре, клик по боковой бусине выводит её в центр;
- ховеры на карточках, ссылках и иконках;
- всё выключается при `prefers-reduced-motion: reduce`.

## Чего ещё нет

Форма заявки из корзины проверяет поля и показывает «Заявка отправлена», но никуда не отправляет: нужно решить, куда слать — Telegram-бот, почта или CRM.

## Тестовый деплой

В проекте лежат два готовых конфига — какой сработает, зависит от того, куда положите код. Оба собирают статику и публикуют её при каждом пуше в `main`.

### GitHub Pages — `.github/workflows/pages.yml`

1. Создать репозиторий, запушить код.
2. Settings → Pages → Build and deployment → Source: **GitHub Actions**.
3. Если имя репозитория не `sinnergems` — поправить `BASE_PATH` и `NEXT_PUBLIC_BASE_PATH` в шапке workflow.

Сайт появится по адресу `https://<логин>.github.io/<репозиторий>/`.

**Важно:** на бесплатном тарифе GitHub Pages публикуется только из **публичного** репозитория, и сам сайт в любом случае открыт всем. Приватный исходник для Pages требует GitHub Pro.

### GitLab Pages — `.gitlab-ci.yml`

1. Создать проект, запушить код — пайплайн запустится сам.
2. Если имя проекта не `sinnergems` — поправить `BASE_PATH` и `NEXT_PUBLIC_BASE_PATH` в `variables`.

Сайт появится по адресу `https://<логин>.gitlab.io/<проект>/`.

У GitLab репозиторий может оставаться приватным на бесплатном тарифе, а сам сайт закрывается настройкой Settings → General → Visibility → Pages → **Only project members**.

### Про подпапку

На Pages сайт живёт не в корне домена, а в подпапке `/<имя-репозитория>`. Поэтому в CI задаются две переменные — `BASE_PATH` (для Next) и `NEXT_PUBLIC_BASE_PATH` (для путей к картинкам, см. `lib/asset.ts`). На своём домене их просто не задают, и префикса нет — код при переезде не меняется.

Побочный эффект подпапки: `@font-face` для TT Firs Neue ссылается на `/fonts/...` от корня домена, так что в превью на Pages шрифт не подхватится. На боевом домене всё работает. Когда придут файлы шрифта, правильнее подключить их через `next/font/local` в `app/layout.tsx` — тогда Next сам разложит пути под любой basePath.

### Переезд на свой сервер

Код не меняется. Меняется способ запуска: вместо статики — `npm run build && npm start` на сервере с Node (или Docker-образ). Как только появится админка Payload, статическая сборка перестанет подходить — понадобится Node и PostgreSQL.
